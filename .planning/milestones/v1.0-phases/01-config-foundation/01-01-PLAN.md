**Step 1 — Add AccessConfig interface to `src/types.ts`:**

Add the following interface after the existing `BlockedConfig` interface (around line 48):

```typescript
/** Access control configuration from config/access.json */
export interface AccessConfig {
  /** true = public mode (anyone can publish unless blacklisted)
   *  false = private mode (only whitelisted pubkeys can publish) */
  public: boolean;
  /** Hex pubkeys always allowed (in public+payments mode, also skip payment) */
  whitelist: string[];
  /** Hex pubkeys always denied (in public mode; ignored in private mode) */
  blacklist: string[];
}
```

Follow the existing pattern: flat interface, JSDoc comments, string arrays. Place it directly after `BlockedConfig` since they are both config file schemas.

**Step 2 — Create `src/middleware/access.ts`:**

Create the new file with these components:

1. **Imports:** `AccessConfig` from `../types.ts`, `StorageClient` from `../storage/client.ts`, `isValidPubkey` from `../util.ts`.

2. **Constants:** `ACCESS_CACHE_TTL_MS = 60_000` (matches `BLOCKED_CACHE_TTL_MS` in `metadata.ts`).

3. **Internal `AccessCache` interface:** Contains `config: AccessConfig`, `whitelist: Set<string>`, `blacklist: Set<string>`, `expires: number`. The Sets provide O(1) lookup for Phase 2.

4. **Module-level cache variable:** `let accessCache: AccessCache | null = null;` — exact same pattern as `blockedCache` in `metadata.ts`.

5. **`DEFAULT_ACCESS_CONFIG` constant:** `{ public: true, whitelist: [], blacklist: [] }` — used when `config/access.json` is missing (CFG-07).

6. **`filterPubkeys(list: unknown, fieldName: string): string[]` internal function:** Validates each entry using `isValidPubkey()` from `util.ts`. Logs `console.warn("[access] Skipping invalid pubkey in config.{fieldName}: ...")` for each invalid entry (CFG-06). Returns only valid 64-char hex entries. If `list` is not an array, returns `[]`.

7. **`normalizeAccessConfig(raw: unknown): AccessConfig` internal function:** Handles `null`/missing → returns `DEFAULT_ACCESS_CONFIG` (CFG-07). Validates `public` field: if not boolean, defaults to `true`. Filters `whitelist` and `blacklist` through `filterPubkeys()`. Returns a structurally valid `AccessConfig` regardless of input quality.

8. **`export async function loadAccessConfig(storage: StorageClient): Promise<AccessCache>`:** Check `accessCache` freshness against `Date.now()`. If fresh, return cached. If stale or null, call `storage.getJson<unknown>("config/access.json")` (returns `null` on 404). Pass result through `normalizeAccessConfig()`. Build new `AccessCache` with `new Set()` for whitelist and blacklist. Set `expires` to `now + ACCESS_CACHE_TTL_MS`. Store in module-level `accessCache`. Return.

Mirror the `isBlocked()` function structure from `metadata.ts` as closely as possible. Use the complete implementation sketch from `01-RESEARCH.md` (lines 340-402) as the reference.

Add a code comment near `ACCESS_CACHE_TTL_MS` noting the 60-second propagation window for config changes, matching the existing comment pattern.
