<feature>
  <name>checkAccess — pubkey access control decision function</name>
  <files>src/middleware/access.ts</files>
  <behavior>
    Decision matrix (from 02-RESEARCH.md):

    | Mode    | Pubkey state      | Result                                              | Req   |
    |---------|-------------------|-----------------------------------------------------|-------|
    | public  | not blacklisted   | { allowed: true }                                   | ACL-01 |
    | public  | blacklisted       | { allowed: false, reason: "pubkey is blacklisted" } | ACL-02 |
    | public  | whitelisted       | { allowed: true } (whitelist ignored)               | ACL-03 |
    | private | whitelisted       | { allowed: true }                                   | ACL-04 |
    | private | not whitelisted   | { allowed: false, reason: "..." }                   | ACL-05 |
    | private | on blacklist only | { allowed: false, reason: "..." } (blacklist ignored)| ACL-06 |

    ACL-07: Function signature is `checkAccess(storage: StorageClient, pubkey: string): Promise<AccessResult>` — no request/body parameter, ensuring callers must invoke it before body read.

    Cases for tests:
    1. Public mode, clean pubkey → allowed (ACL-01)
    2. Public mode, blacklisted pubkey → denied, reason contains "blacklisted" (ACL-02)
    3. Public mode, whitelisted pubkey → allowed (whitelist has no effect) (ACL-03)
    4. Public mode, pubkey on BOTH lists → denied (blacklist wins in public) (ACL-02 edge)
    5. Private mode, whitelisted pubkey → allowed (ACL-04)
    6. Private mode, clean pubkey → denied, reason is user-facing (ACL-05)
    7. Private mode, blacklisted-only pubkey → denied (blacklist ignored) (ACL-06)
    8. Private mode, pubkey on BOTH lists → allowed (whitelist wins in private) (ACL-04 edge)
  </behavior>
  <implementation>
    1. Add `AccessResult` type to `src/middleware/access.ts` as a discriminated union:
       - `{ allowed: true }` or `{ allowed: false; reason: string; requiresPayment?: true }`
       - Export the type for handler use in Phase 3
       - The `requiresPayment` field is RESERVED for v2 only — do NOT set it in any return path

    2. Add `checkAccess(storage: StorageClient, pubkey: string): Promise<AccessResult>`:
       - Call `loadAccessConfig(storage)` to get the cached AccessCache
       - If `cache.config.public` (public mode):
         - If `cache.blacklist.has(pubkey)` → `{ allowed: false, reason: "pubkey is blacklisted" }`
         - Else → `{ allowed: true }` (do NOT check whitelist — ACL-03)
       - Else (private mode):
         - If `cache.whitelist.has(pubkey)` → `{ allowed: true }`
         - Else → `{ allowed: false, reason: "This server requires explicit access. Contact the operator." }` (do NOT check blacklist — ACL-06)
       - Comment each branch with requirement IDs

    3. Include the decision matrix as a comment block above the function for maintainability.

    Anti-patterns to avoid:
    - Do NOT check whitelist in the public branch (ACL-03 violation)
    - Do NOT check blacklist in the private branch (ACL-06 violation)
    - Do NOT set requiresPayment in any return path (v2 reserved)
    - Do NOT add request/body parameters to the signature (ACL-07 — caller contract)
  </implementation>
</feature>
