**1. Add types to src/types.ts** (append after existing PaymentInfo interface):

Add these interfaces:
- `MintEntry` — `{ url: string }` (minimal; future phases add optional fields)
- `PaymentAmounts` — `{ upload: number; mirror: number }` (satoshis; 0 = free; delete excluded by design)
- `PaymentConfig` — `{ mints: MintEntry[]; amounts: PaymentAmounts }` (operator input, distinct from existing `PaymentInfo` which is 402 response output)
- `CacheConfig` — `{ accessTtl: number; paymentTtl: number; blockedTtl: number }` (milliseconds internally)

Add JSDoc to each interface explaining its purpose. Note on PaymentConfig: "Operator configuration from config/payment.json — NOT the same as PaymentInfo (which is the 402 response format)."

**2. Create src/middleware/payment-config.ts** following the exact pattern from src/middleware/access.ts:

Constants:
- `DEFAULT_PAYMENT_AMOUNTS: PaymentAmounts = { upload: 0, mirror: 0 }`
- `DEFAULT_PAYMENT_CONFIG: PaymentConfig = { mints: [], amounts: { upload: 0, mirror: 0 } }`

Functions to implement:
- `isValidMintUrl(url: unknown): boolean` — checks `typeof url === "string"`, wraps in `try { new URL(url) }`, returns `parsed.protocol === "https:"`. Format check only, NO network probing.
- `normalizeMints(raw: unknown): MintEntry[]` — if not array return []. Iterate entries, skip non-objects with console.warn, skip entries with invalid URLs with console.warn (pattern: `[payment] Skipping mint with invalid URL: "..."`), push valid `{ url: entry.url }`.
- `normalizeAmounts(raw: unknown): PaymentAmounts | null` — if not object return default amounts. For each of "upload", "mirror": if value present and (not number OR not integer OR negative), console.warn and return `null` (reject entire config per CONTEXT.md). Otherwise extract valid values, default missing to 0.
- `normalizePaymentConfig(raw: unknown): PaymentConfig` — if null/non-object return default. Extract amounts via normalizeAmounts — if null, return default (disabled). Extract mints via normalizeMints. Return `{ mints, amounts }`.
- `paymentsEnabled(config: PaymentConfig): boolean` — returns `config.mints.length > 0`. This is the ONLY enabled check. Do NOT check amounts > 0.

Cache and loader (same pattern as loadAccessConfig):
- Interface `PaymentCache { config: PaymentConfig; expires: number }`
- Module-level `let paymentCache: PaymentCache | null = null`
- Use a hardcoded 60_000ms TTL for now (Phase 5 will wire CacheConfig.paymentTtl to replace this)
- `loadPaymentConfig(storage: StorageClient): Promise<PaymentCache>` — check cache TTL, fetch `config/payment.json` via `storage.getJson<unknown>()`, normalize, cache, return
- `_resetPaymentCacheForTesting(): void` — sets cache to null

Export: `normalizePaymentConfig`, `paymentsEnabled`, `loadPaymentConfig`, `_resetPaymentCacheForTesting`

**1. Create src/middleware/cache-config.ts** following the access.ts normalizer pattern:

Constants:
- `DEFAULT_CACHE_TTL_MS = 60_000` — 60 seconds, matches current hardcoded behavior in access.ts and metadata.ts
- `TTL_FLOOR_MS = 1_000` — 1 second minimum (TTL=0 maps here per CONTEXT.md decision)
- `TTL_CAP_MS = 86_400_000` — 24 hours maximum (Claude's discretion: reasonable cap)
- `DEFAULT_CACHE_CONFIG: CacheConfig = { accessTtl: 60_000, paymentTtl: 60_000, blockedTtl: 60_000 }`

Functions to implement:
- `clampTtl(raw: unknown): number` — if not finite number, return DEFAULT_CACHE_TTL_MS. Convert from seconds (JSON) to milliseconds (internal) with `Math.round(raw) * 1_000`. Clamp: `Math.min(Math.max(ms, TTL_FLOOR_MS), TTL_CAP_MS)`. This means TTL=0 in JSON → `0 * 1000 = 0` → clamped to `TTL_FLOOR_MS = 1000`.
- `normalizeCacheConfig(raw: unknown): CacheConfig` — if null/non-object return default. For each field (accessTtl, paymentTtl, blockedTtl): if present, clamp via clampTtl; if absent, use DEFAULT_CACHE_TTL_MS.

Cache and loader:
- Interface `CacheConfigCache { config: CacheConfig; expires: number }`
- Module-level `let cacheConfigCache: CacheConfigCache | null = null`
- Use hardcoded 60_000ms TTL for the cache config's own cache (the cache config itself is cached for 60s — this is a meta-cache, not configurable by the cache config it loads)
- `loadCacheConfig(storage: StorageClient): Promise<CacheConfig>` — check cache, fetch `config/cache.json`, normalize, cache, return the CacheConfig (not the wrapper — downstream consumers need the config directly)
- `_resetCacheCacheForTesting(): void` — sets cache to null

Export: `normalizeCacheConfig`, `loadCacheConfig`, `_resetCacheCacheForTesting`
